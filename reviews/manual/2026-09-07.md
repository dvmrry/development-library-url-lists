# Initial scope review — September 7, 2026

Advisory review of three candidates from different ecosystems, using official
documentation. These conclusions do not change the approved catalog or tenant
policy. Live package downloads and internal artifact-service configuration were
not tested.

| Candidate | Evidence | Recommended next decision |
| --- | --- | --- |
| `npm.jsr.io` | JSR documents this domain as its npm compatibility API for package metadata and tarball downloads. [Official API reference](https://jsr.io/docs/api), [npm compatibility](https://jsr.io/docs/npm-compatibility) | Good candidate for an exact JavaScript registry entry after owner approval. Existing `jsr.io` exact coverage does not cover this subdomain. |
| `mirror.gcr.io` | Google documents this host as its managed cache for public Docker Hub images, with Docker falling back to Docker Hub for cache misses. [Official documentation](https://docs.cloud.google.com/artifact-registry/docs/pull-cached-dockerhub-images) | Good candidate for an exact container-mirror entry after owner approval. Evaluate cache and fallback traffic together when configuring internal upstream access. |
| `ci.appveyor.com` | AppVeyor documents NuGet feeds below `/nuget/` and other functionality, including an encryption tool below `/tools/encrypt`, on the same host. [NuGet feeds](https://www.appveyor.com/docs/nuget/), [deployment documentation](https://www.appveyor.com/docs/deployment/nuget/) | Hold whole-host promotion. Package use is supported, but scope is shared. Investigate a `/nuget/` path rule with actual enforcement behavior and traffic before choosing a target. |

The first two are documentation-supported candidates, not proof of safe or
complete enforcement. The third demonstrates why confidence and blocking scope
must be reviewed separately. Follow-on traffic comparisons can be run with
`scripts/audit_traffic.py` and retained under `.private/`.
